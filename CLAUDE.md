# Night City Trainer — notes for contributors and agents

- **Stack:** TypeScript, React 18 and Vite 8, with Vitest 5 for tests and tsx for scripts. No backend. The site is a static build for GitHub Pages (`base: './'`, hash routing), deployed by `.github/workflows/pages.yml` (official Pages actions; a `check` job runs `npm run typecheck`, tests, lint, `check:data` and the build on every push and PR, and `deploy` publishes pushes to `main`; actions pinned by SHA).
- **Engine:** `src/engine/engine.ts` (Game class) implements the Comprehensive Rules saved in `data/raw/official_comprehensive_rules.txt`. Card behaviour lives in `src/engine/scripts/<color>.ts`, keyed by card id from `src/data/cards.json`.
  - `Game` is a facade: setup, the turn loop, accessors and the log are in `engine.ts`; every other method hands over to the function of the same name in `src/engine/game/` (`mods`, `economy`, `zones`, `gigs`, `choices`, `pending`, `history`, `actions`, `combat`), which takes the game first. Scripts, bots and tests keep calling `g.method()`; put new rules code in the module it belongs to, with a one-line method on `Game` if callers need it.
  - Scripts use the `CardScript` hooks in `src/engine/types.ts`.
  - Opt-in agent flags on `Agent` (`types.ts`): `choosesPayment`, `choosesOrder` and `confirmsEndTurn` (a main phase whose only legal action is pass asks the one-option 'action' decision instead of ending the turn by itself). Only human seats set them; bots, clones and play-outs never do, so bot games and pins don't move.
  - When an effect does nothing because its condition fails or it has no target, the log says why: `noEffect()` in `scripts/helpers.ts` (`pick()` logs an empty candidate list itself). Log only (bots never read the log; clones and probes don't log), and only facts both players can see.
  - State must stay plain data, because `Game.clone()` / `probeCopy()` copy it with `copyState` (`src/engine/copyState.ts`, generic, throws on a Map, Set, Date or class instance; `tests/copy-state.test.ts` checks it against `structuredClone`). `Mod` is a discriminated union on `kind` (`ModKinds` in `types.ts`): add a kind there before using it. Never put functions in mods; player `costMod` filters are plain objects (`CostModFilter`, see `costModMatches`). A `'startOfTurn'` mod must name `untilPlayer` (the types and `modDuration` refuse one without).
  - "Next time … this turn" effects from Programs use `g.addDelayed(self, event, data)` together with a `delayed` handler on the script.
  - "First time … each turn" effects read the engine's per-turn history (`g.firstThisTurn(ev.seq, kind, pred)`, `g.turnCount`), not per-card markers.
  - `Game.clone()` drops the log by default; pass `{ keepLog: true }` to keep it (the Play undo snapshot in `src/lib/practiceSession.ts` does).
- **Card data:** `npm run build:data` (`tools/build-data.ts`) regenerates `src/data/cards.json` from `data/raw/sim_catalog.json`.
- **Bundled data in the UI:** read `src/data/*.json` through the typed views: `src/data/index.ts` (types, and `RATINGS` / `SEASONS` / `REVIEW`), and one module per large file (`analysisData.ts`, `deckReportsData.ts`, `tournamentIndex.ts`). The Home page is in the entry chunk, so it must not import a large file statically (`tests/home-data.test.tsx` checks; Home loads the deck reports at runtime). `allDecks()` is cached against the stored custom decks and returns a read-only list. The next event's date is in `src/content/event.ts`.
- **`data/raw/`** (rules text, card catalog, choom.gg pages) is gitignored and local-only: it is not in the repository or the site, so a fresh clone can't run `build:data` or the choom.gg imports.
- **Decks:** `data/decks/*.txt` (meta-*, guide lists) and `data/decks/custom/`: `LIBRARY_DIRS` and `libraryDeck()` in `src/lib/library.ts` are the one rule both loaders use (`loadLibrary` in `scripts/lib-node.ts`, `BUILTIN` in `src/lib/browserLibrary.ts`). Retired lists live in `data/decks/archive/` (not loaded by the site or `loadLibrary`; notes in `src/content/deckObjectives/archived.ts`). Parse and export them with `src/engine/deck.ts`. Choom.gg imports are refreshed with `scripts/import-meta.ts` and `scripts/import-guides.ts`.
- **Bots:** `src/ai/heuristic.ts` (1-ply lookahead; set `deep: N` for turn rollouts), `src/ai/eval.ts` (weights: `TUNED_WEIGHTS` are the ones `scripts/tune.ts` searches by default; the rest, such as `playOutClamp` and `win`, are fixed defaults; `evaluateTerms()` gives the per-term features that `scripts/eval-calibrate.ts` fits against results; `DEFAULT_WEIGHTS` is the fitted set `calibrated-2026-11` + `rivalLethal` 400 since SIM_VERSION 6, used by Medium, Hard and the coach (Easy never reads the weights); named sets, including the old hand weights `hand-2026-10`, are in `src/ai/weightSets.ts` and picked in a bot spec with `"weightSet"`), `src/ai/knowledge.ts` (roles, ratings, Gig plans). Every lookahead that plays a move out (deep rollouts and reactions, the reviewer's oracle, `scripts/review-debug.ts`) uses `playOut()` and `makeWorlds()` in `src/ai/playOut.ts`. Docs are in `docs/BOT_TOOLKIT.md`.
  - Package terms: `src/ai/packages.ts` gives a seat the synergy packages its own list is built around (cached by list fingerprint, never in state) and per-position facts. The weights `pkgHold`, `pkgAssembly`, `pkgSteer` and `pkgProtect` in `EvalWeights` are 0 by default, and all 0 is the old bot exactly. Only the deciding seat's own packages count; lookahead clones give the rival seat none (`withoutPackages`). Measure a change with `scripts/package-scoring.ts --out <scratch dir>` (paired games, decisions changed, scarce pieces sold). The coach's package wording is `packageNotes` / `packageWarnings` in `src/ai/coach.ts`, gated by the measured lift in the synergy report (`src/ai/packageLift.ts`: a package is named only when its online-vs-never interval is above 0, worded as an association; with no report, as an unmeasured idea); the Play page loads the report at runtime and sends the seat's table in `CoachRequest.lift`.
  - Position benchmark (INFO-5, docs/BOT_TOOLKIT.md §10): `data/benchmark/suite.json` holds Hard-vs-Hard decision positions stored as seed + decks + the answers before them and rebuilt by replay (`pauseAt` in `src/ai/benchmark.ts`), each option labelled by play-outs to the end of the game with Medium bots in shared worlds (stats in `src/lib/benchmarkStats.ts`). `npx tsx scripts/benchmark.ts <bot> [<bot 2>]` reports regret by decision type and stage in a few seconds, but as built it does not separate Easy from Hard (the labels depend on the continuation bot), so it is not a yardstick yet; `scripts/benchmark-build.ts --force` rebuilds the suite (about 35 minutes). The position replays depend on the engine, the oracle's labels on the Medium bot as well: a change to either fails `tests/benchmark.test.ts`, and the suite must then be rebuilt (last rebuilt 2026-11-12 for SIM_VERSION 6; version 7 changed only Hard, and the suite still passes).
- **Sims:** `npm run sim -- <catalog|show|vs|test|review|analyze|add>` runs games in worker threads (`scripts/worker.ts`, booted via `worker-boot.mjs`). Both worker pools are a `WorkPool` (`src/lib/workPool.ts`) with a thin adapter and a crash policy: `workerPool()` in `scripts/lib-node.ts` (worker_threads; a crashed job is retried once) and `GamePool` in `src/sim/pool.ts` (Web Workers; a crashed game fails). `runJobs` keeps one game pool per process (`gamePool()`), so later batches reuse its workers. `--cache` on botcheck, tune, forge, optimize and rank-stability reads games already played from `.cache/games/` (gitignored; `scripts/game-cache.ts`: keyed on the whole job, `SIM_VERSION`, the Node version and a hash of every file the game worker loads). Other scripts: `scripts/tune.ts` (weight tuning), `scripts/optimize.ts` (card-swap search), `scripts/botcheck.ts` (compare bot configs: duplicate format, each deal played twice with the configs swapped, paired interval from `duplicateSummary` in `src/lib/evidence.ts`), `scripts/rank-stability.ts` (SIM-3: the same round robin under two or more bots on the same deals; Spearman rank correlation with a paired bootstrap, and the decks whose rank or Sim-tier band moved beyond the noise; maths in `src/lib/rankStability.ts`).
- **Tournaments:** the rules (Swiss, top cut, Bo1/Bo3, seeds) live in `src/lib/tournament.ts`, shared by `npm run tournament -- --field meta --bo 3 --top 8 --bot deep` and the in-browser runner (`#/run`, games run in `src/sim/game.worker.ts` via `src/sim/pool.ts`). Other formats and hand-arranged events (pairings set by hand, manual top-cut seeds, a fixed bracket, round robin and groups, a match list, Bo5 and best-of per bracket round, first-player rules) are an `EventSetup` in `src/lib/eventFormats.ts` (pure, re-exported by `tournament.ts`; the CLI builds it in `scripts/tournament-setup.ts`, the runner's form is `src/lib/eventDraft.ts`). Default Swiss rounds and top cuts keep the table seed scheme, so a plain event is byte-identical to before (pinned in `tests/event-formats.test.ts`); anything arranged uses keyed seeds (event seed + a stable match key). A non-plain event records `setup`, and `custom: true` unless it is a standard Swiss event: custom events count for ratings and head-to-heads game by game, never for titles, top 8s, finishes or Swiss records (`scripts/event-pool.ts`). Round by round uses `beforeRound`; Resume re-runs the setup with `resumePlay`. Use `makeBot()` (`src/lib/tournament.ts`) for any game that must replay identically: same code + same seed = same game. Bot and engine fixes change results: every event records `simVersion` (`SIM_VERSION`) and a manifest, and `check:data` fails one without them. Since SIM_VERSION 6 Hard reads no card impact (`impact` 0, plain mulligan; since SIM_VERSION 7 also `sellLookahead: 3`), so re-running `sim analyze` no longer moves recorded games; the coach, `hard-v1` and the deck builders still read `src/data/impact.json`. Recorded games are pinned in `tests/replay-events.test.ts`. Events live in `public/tournaments/` (index `src/data/tournaments.json`); the UI shows their recorded `date` with `RecordedAt` / `formatRecorded` (`src/ui/components/RecordedAt.tsx`). A game that throws is an error in both the CLI and the browser pool (`src/sim/pool.ts`), never a tie.
- **Run manifests:** every result writer attaches one (`src/lib/runManifest.ts`): `gameRunManifest` for runs that play games (CLI scripts, Matchup Lab, Deck Lab), `aggregateManifest` for files pooled from recorded events (`ratings.ts`, `build-h2h.ts`), which is derived from the input events only so an unchanged rebuild stays byte-identical. Deck ids are `deckFingerprint`s. Keep `schema: 1` readable: add optional fields only, or bump the schema. `rulesVersion`, `faqVersion` and `errataVersion` come from `src/lib/rulesVersions.ts` (errata has no published date yet, so it is null); aggregate manifests leave them null. `npm run check:data` (read-only) checks the event index against the event files, h2h coverage, and manifest deck ids against the stored lists.
- **Card impact** (`src/ai/impact.ts`, Deck Lab) is matched by list fingerprint (`listFingerprint`, carried in games as `PlayerState.listId`), never by deck name alone. Every entry in `src/data/impact.json` has its fingerprint (the legacy name table is gone). A less confounded estimate (landmark, by opponent and seat, shrunk; kept vs sold) is written only into an `--out` directory by `npm run sim -- analyze --impact-adjusted --out DIR` (`src/analysis/impactAdjusted.ts`); no bot reads it. `scripts/card-value-check.ts` rank-correlates the hand-written `cardValue` with the measured numbers. `impactSell` / `impactCards` (default `impact`) switch the sell and card-choice uses one by one; `mulligan: 'plain'` drops the mulligan use.
- **Play UI:** the practice-session logic (undo, concede, errors, recording) is in `src/lib/practiceSession.ts`, driven by the `usePracticeGame` hook (`src/ui/usePracticeGame.ts`). Concede is a session verdict, not an engine action: it stops the loop like Quit, then records the game once as a conceded loss. The setup screen is `src/ui/components/PlaySetup.tsx`; the coach's advice comes from `useCoach` (`src/ui/useCoach.ts`, a worker) and its panel, move toast and scorecard are in `board/CoachPanel.tsx`. Drag-to-act and confirm prompts are in `src/ui/components/board/drag.tsx`. Every board overlay, dialog and menu uses `useFocusTrap` (`components/Modal.tsx`): focus in, Tab kept inside, Escape, focus restored; the newest open one takes the keys. Which cards look actionable comes from `boardMarks()` in `board/interaction.ts`, which reads only the pending decision's options. The log drawer is in `board/LogDrawer.tsx`, and bot speed and the session-long panel flags are in `board/prefs.ts`. `layoutMode()` in `board/layout.ts` (via `useViewport()`) picks the layout. On desktop and tablets the board fills the viewport (`.pb-full` in `board.css`; card sizes come from `--cw` / `--tcg-w`). On phones (`.pb-phone`, portrait or landscape) it is fixed to the screen with sizes from `phoneLayout()`. Phones show prompts in the small right-edge panel in `board/PhoneParts.tsx` (also the ☰ game menu and the card reader). On every layout, prompt cards on the table are picked on the board (`promptChoices()`). The hover preview renders in a portal (`TcgCard`). Undo restores a snapshot (game state plus a cloned bot) taken before each human main-phase decision and continues with `Game.resume()`. The board setting "End of turn" (`endTurn` in `boardSettings.ts`, default `click`; site default `play.board.endTurn`) is fixed when a game starts and recorded as `endTurnClick` on the practice replay, save and review spec (`rivalEndTurnClick` for the rival online, `OnlineSetup.endTurnClick` per seat from the hello); absent means automatic, so older records replay unchanged. Multi-day games against a person stay automatic (a click would cost the guest a packet round trip). Board settings (paying costs, the side panel's position and display, accent colours, board and Gig backgrounds) are one versioned key `nct.boardSettings.v1` read through `src/lib/boardSettings.ts` and `src/ui/useBoardSettings.ts`, edited in `board/SettingsDialog.tsx` (⚙ on the strip, ⚙ Settings in the phone ☰ menu, and on the setup screen); accents and backgrounds are CSS tokens in `src/ui/themes.css`. "Choose before/after" payment is a UI layer (`src/lib/eddiePayment.ts`): `answerFor` in Play.tsx holds a costed action until its sources are picked, then answers the engine's own 'pay' decisions from them (`planAnswer`); Automatic is the old path unchanged. Visual replay recording is in `src/lib/replayFrames.ts`. Saved games (`src/lib/savedGames.ts`, UI in `components/SavedGames.tsx`): an autosave (written at each new decision of yours and on page hide; cleared on finish, concede or Exit) and up to 5 named slots in localStorage, export/import as `kind: 'nct-saved-game'`, `schema: 1`. A save is setup + seeds + your answers + coach grades + a position check (state hash at your last decision, `simVersion`); `PracticeSession.restore()` replays it unpaced (rebuilding Undo snapshots) and refuses, never resumes, a save from another `SIM_VERSION` or one that no longer reaches the saved state (its log can still be read). "⤓ Export game" (game-over dialog, phone ☰ menu) saves the replay with the coach's advice, grade and scores per decision (`src/lib/coachedReplay.ts`, `kind: 'nct-coached-replay'`, schema 1; the session keeps the record on each grade, `CoachedGrade`); `scripts/review.ts --from file` reads it.
- **Online play** (`src/net/`, features `multiplayer` and `chat`; lobby and board in `src/ui/pages/PlayOnline.tsx`, lazy-loaded from Play at `#/play/online` and `#/play/join/<code>`): two people, no server. Transport (`transport.ts`): `send` / `onMessage` / `onState` / `close`, implemented by a WebRTC data channel with manual signalling (`webrtc.ts`: the host's invite code and the guest's reply code are each a compressed SDP with its candidates; STUN servers from the site config's `multiplayer.iceServers`, empty = same network only), a `BroadcastTransport` for two tabs of one browser (room code, reconnects by itself), and `loopbackPair()` for tests. Protocol (`protocol.ts`): versioned JSON (`v: 1`), every message parsed into a fresh capped object and refused (noted, never acted on) when malformed; legality now (an answer to the decision actually waiting, by `seq` and option index) is checked by the session. The host's browser runs the real `Game` (`hostGame.ts` `HostGame`: both seats are people; per-seat answers recorded; optional turn timer answering with `defaultAnswer`; concede/abandon are session verdicts) and sends the guest only `viewFor(state, 1)` (`view.ts`, pure: the seat turned round to player 0; both decks, the rival's hand, every Eddie and face-down Legends the seat doesn't know masked with positional stand-in uids ≥ `HIDDEN_BASE`; `rng` zeroed; the rival's unseen sells/adds unnamed in the log) plus its own decision (`viewDecision`). The host's own board also draws `viewFor(state, 0)`, through `ViewGame`. Trust model (said in the lobby): the host's device runs the game, so it is for friendly play; a modified host could see hidden cards. First player: commit-reveal roll (`fair.ts`) picks who chooses (rule 7.5). Sessions (`session.ts` `OnlineHost` / `OnlineGuest`): lobby (deck checked with `validateDeck`; only deck names are shown), heartbeat and "connection lost", reconnection (the guest's resume token `nct.online.guest.v1`; the host's save `nct.online.host.v1` = setup + seed + both seats' answers + a state-hash check, restored by replay), chat (`chat.ts`: plain text, 300 characters, rate-limited, mute; kept only in an export), rematch. A finished game is recorded once per side (`record.ts`): practice log `level: 'pvp'` with `rival`, and a replay with `pvp` (seat, rival answers) so the Game review replays both seats; the guest gets the record (seed and answers) from the host only after the game is over. Profile shows them as "vs players", never in a bot tier. PvP games never touch bots, ratings, events or `SIM_VERSION`. Tests: `tests/online.test.ts`, `tests/online-ui.test.tsx`.
- **Multi-day games** (feature `multiDayGames`; the site config's `multiDay` range 3–20 days, default 7, and `maxOngoing` cap 8): no server, so nothing waits online. Against the bot (`src/lib/multiDay.ts`): the Play setup's "Multi-day game" choice starts an ordinary practice game whose save (the saved-games record: setup + seeds + answers + position check) goes to its own list `nct.multiDay.bot.v1`, never the autosave (`usePracticeGame` routes `onStable`/flush by replay id; Exit keeps it, finish/concede removes it and records it with `multiDay` on the practice entry and replay); resumed with `PracticeSession.restore` like a save. Its deadline (start + days) is never enforced silently: past it the list offers "Finish it anyway" (recorded `late`) or "Close as a timed-out loss" (`timedOutRecords`: a loss and a replay that stops there). Against a person, by turn packets (`src/net/packet.ts`, `corr.ts` light types/clock/list, `corrStore.ts` full checks and store `nct.corr.v1` keyed by game id + role, `corrSession.ts` `CorrSession`; UI `src/ui/pages/PlayCorr.tsx`, lazy, at `#/play/corr`, `#/play/corr/<id>/<role>`, packet links `#/play/turn/<code>`): the host's device runs a `HostGame` restored from its save; the invite carries the host's key half and roll commitment, the reply the guest's deck, key half and roll secret (+ first-or-second preference and "automatic payment/order", which the host answers with option 0). Packets: `T` + deflate + base64url of MAC + JSON (`n`, previous MAC `p`, sender stamp `t`), HMAC-SHA-256 with the game key; refused when edited, from another game, replayed, out of order or forked (`chainProblem`; a verdict that crosses the other side's packet is accepted). The host sends the guest `viewFor(…, 1)` as a patch to the last view sent (`diffView`/`applyPatch`, `viewHash` check), the new log lines and its decision; the guest sends one answer per packet (each guest decision is a round trip). Clock: each player has half the game's length, running from the rival's packet stamp to their own; when it runs out the other player may claim the win (`HostGame.timeLoss`, end why `timeout`) or give more time (rides in the next packet). Recorded once per side as `pvp` with `multiDay`. Ongoing games panel: `components/OngoingGames.tsx`; the Play tab's count is `src/lib/ongoingBadge.ts` (entry chunk, raw JSON only). No live switch for these games. Tests: `tests/multi-day-bot.test.tsx`, `tests/multi-day-corr.test.ts` (leak search shared in `tests/netLeak.ts`).
- **Game review** (docs/BOT_TOOLKIT.md §8): a rating for every move of a finished practice game (Inspired, Sharp, Best, Close call, Slip, Mistake, Blunder, or not counted), defined in Gigs with the paired SE in `src/lib/gameReview.ts` and run by `runGameReview` (`src/sim/gameReviewRun.ts`), the one function the review worker and `scripts/review.ts --from file` share; your coach-graded moves keep the coach's grade; the screen is `src/ui/components/GameReview.tsx` (the old "Full match review" is its second tab), stored in `nct.gameReviews.v1` (`src/lib/gameReviewStore.ts`); `scripts/game-review-check.ts` measures the ratings and their stability.
- **Rules FAQ conformance:** `tests/faq/matrix.ts` (entries in `tests/faq/entries/`) lists every official FAQ ruling by id with our card id, a one-line paraphrase (never the FAQ's wording), a status and its test in `tests/faq/*.test.ts` (titles name `faq:<id prefix>`). The FAQ itself is local-only (`data/raw/official_rules_faq.json`). When it updates: refresh that file, run `npx vitest run tests/faq` (the consistency test lists new and removed ruling ids), triage them in the matrix, then set `FAQ_VERSION` in `src/lib/rulesVersions.ts` to the file's `updated_at`.
- **Deck objectives** (`src/content/deckObjectives/`): one strategy note per library deck (objective, plan, key cards, success signals in a shared vocabulary, risks), keyed by file and tied to the list by `listFingerprint`; shown as "Game plan" on the deck profile. `tests/deck-objectives.test.ts` fails when a deck has no note, a list changed (update `listId` after re-checking the note) or a term is undefined. The owner edits an entry and sets `status: 'owner'`; sim-ladder decks are `needs-owner` placeholders.
- **Profile** (`#/profile`, sub-pages `#/profile/history|decks|my-decks|sharing`, `src/ui/pages/Profile.tsx`, parts in `components/ProfileParts.tsx`): lives in this browser only. `src/lib/profile.ts` stores only the choices (`nct.profile.v1`, `kind: 'nct-profile-settings'`, schema 1: name, picture card id, favourite deck file, per-section public flags, all private by default); every number is derived at read time from the practice log by `src/lib/profileStats.ts` (the log entry also keeps Gigs and the coach scorecard, `annotatePractice`). Sharing (`src/lib/profileShare.ts`) builds a `kind: 'nct-profile'`, schema 1 document of the public sections only (`buildShared`; `tests/profile.test.ts` checks a private section leaves nothing behind), carried as a link `#/u/<payload>` (deflate-raw + base64url, capped at `LINK_MAX`; a file otherwise). The viewer route `#/u/` validates it with `parseShared` (untrusted: strings cleaned and capped, rendered as text only, newer schema refused). Saved decks record `added` and `origin` (imported / created) for "My decks".
- **Site config** (docs/SITE_CONFIG.md): `public/site-config.json` is the owner's switchboard (title, nav tabs and pages, features, banner, Home sections, Play defaults, deck hiding, maintenance). Schema, defaults (= the site as before), parser and rules (`pageOn`, `visibleNav`, `bannerActive`) are pure in `src/lib/siteConfig.ts`; the committed file must parse to exactly the defaults (`tests/site-config.test.tsx`). The build inlines it into index.html (plugin in `vite.config.ts`, no flash) and `src/ui/useSiteConfig.ts` re-fetches it; read it with `useSiteConfig()` / `useFeature()` / `featureEnabled()`, and gate links to pages the owner can turn off with `IfPage` (`components/SiteChrome.tsx`). A new feature flag goes into `FEATURES`; a new page into `NAV_CATALOG`. The editor is `#/admin` (`src/ui/pages/Admin.tsx`, lazy, not in the nav, not a security boundary). `check:data` validates the file.
- **Deck Lab** (`#/lab`, `src/lib/deckLab.ts`) tunes a submitted deck (browser forge) and breeds decks in the browser.
- **Tuned decks** (`#/tuned`, `src/ui/pages/TunedDecks.tsx`, logic in `src/lib/tunedDecks.ts`) lists the Lab's tuned decks saved in this browser from `StoredDeck.tuned`, with Export all / Import (`kind: 'nct-tuned-decks'`, schema 1; import skips lists already saved by `listFingerprint`) and the library's `// Forged` lines (`forgedBuiltins()`).
- **Deck gallery** (`#/decks`, `src/ui/components/DeckGallery.tsx`): one grid; source keys come from `deckSource()` (`src/lib/deckSource.ts`), and the view (filters, sort, grouping) is plain data in `src/lib/galleryView.ts`, kept in the hash query via `history.replaceState` (a hashchange would remount the page) and in `nct.gallery.view.v1`.
- **Deleting and hiding decks** go through `useDeckActions()` (`components/DeckActions.tsx`: confirm Modal, then an Undo toast; `deleteCustomDecks` / `restoreCustom` in `browserLibrary.ts`). Built-in decks can only be hidden (`src/lib/hiddenDecks.ts`, `nct.hiddenDecks.v1`); pickers skip hidden decks except the one picked. Library writes fire `LIBRARY_CHANGED`; pages that show the library call `useLibraryVersion()` (`src/ui/useLibrary.ts`) to follow saves, deletes and hides here or in another tab.
- **Sim tier** (`src/lib/simTier.ts`): our S–D letter from `ratings.json` (expected win rate vs the field, fixed bands, unrated under `SMALL_SAMPLE` games, ± when the 90% range reaches `SIM_TIER_STRADDLE_BANDS` bands away), computed at read time. Show it with `SimTierBadge` / `TierPair` (`components/TierBadges.tsx`, `DeckIdentity.tsx`), always beside, never instead of, choom.gg's tier (`ChoomTierBadge`). The page leads with the current list against the ORIGINAL on one common held-out block (`vsOriginal` in `TuneOptions`; `trajectoryLine`, `tuneSummaryText`; `TuneTrajectory` in `LabEvidence.tsx`): a per-generation "baseline" is that generation's own screening games and is never shown as a trend. A saved tuned list carries a `tuned` record (`src/lib/tuneRecord.ts`, `StoredDeck.tuned`) and the manifest's optional `tune` field.
- **Partner-aware cuts** (`src/lib/cutRanking.ts`; docs/SYNERGIES.md "Partner-aware ranking"): one shared ranking for the forge, optimizer and Lab tuner (partner-present score with shrinkage, stranding cost from `holdOdds`, add credit). CLI opt-in (`--partner-aware`, or any package flag; `--plain-ranking` off), Lab on by default; without it the pinned candidates are unchanged. The coach explains sells with it and breaks near-ties (`sellKeepScarce`); bots never use it (`pkgHold` stays 0). Its synergy controls are in `src/ui/components/LabPackages.tsx`: keep toggles (default: the packages the deck objective names, else the ones the list is built around), package moves off by default, and a picker of one or two packages to breed around. Its evidence views (outcome chip, paired gain with interval and games, the Search depth fieldset with the game estimate) are in `src/ui/components/LabEvidence.tsx`.
- **Deck-change adoption** (`src/lib/evidence.ts`; docs/SYNERGIES.md "When a deck change is adopted"): the forge, optimizer, season forge step and Lab tuner share one rule. Screening only nominates; nominees are confirmed on fresh held-out seeds, paired game for game with the current list, in stages up to `capStages` × the first stage; the outcome is `adopt` / `reject` / `inconclusive` ("could not tell": never adopted, never called a gain) against `minGainPp`; nominees split α by Bonferroni and each one's share is spent over the looks by O'Brien–Fleming-type boundaries (`src/lib/groupSequential.ts`; `boundary: 'bonferroni'` / `--boundary bonferroni` is the older even split, and the manifest's `adoption.correction` records which ran). Defaults are `ADOPTION_DEFAULTS`; `--adopt any-gain` (Lab: `rule: { kind: 'any-gain' }`) is the legacy rule, and the manifest's optional `adoption` field records which rule ran. Always report the held-out figure, never the screening one. Search depth (cards and packages per change, nominees) and the game estimate are in `src/lib/deckSearch.ts`, the flags in `scripts/evidence-flags.ts`. `scripts/tuning.ts` re-exports `summarizePaired` and `DEFAULT_MIN_GAIN_PP` from `evidence.ts`.
- **Decision telemetry** (`docs/DECISION_TELEMETRY.md`): `g.telemetry = new DecisionRecorder()` (`src/engine/telemetry.ts`) records every decision, observe-only (clones never record); `src/analysis/decisions.ts` reports card use by mode, stage and Gig standing as association, not value. `npm run sim -- analyze --decisions [--out DIR]`.
- **Synergy packages** (`docs/SYNERGIES.md`): the catalogue is `src/content/synergies/` (human-edited drafts like the deck objectives: members by id or by a class the payoff names, roles, `needs`, `builtAround`, an `online` condition over the small `CONDITION_TERMS` vocabulary; `synergiesIn(deck)` gives a list's packages and draw odds). `tests/synergies.test.ts` fails on an unknown card, an undefined term or an unconfirmed proposal. `npm run sim -- analyze --synergies` (or `--synergies-only`, which writes nothing else) measures them from optional board snapshots (`new DecisionRecorder({ boards: true })`) into `reports/synergies-latest.*` and `public/data/synergies.json` (Card stats → Synergies, deck profile); association, not value, and nothing in the bots reads it. The deck builders use packages through `src/lib/deckPackages.ts` (plain data, Node and browser): a `PackagePlan` (keep / require / avoid / lockCards) checked by `checkChange` / `checkList` before any candidate is played, package moves (complete, add, swap, remove), and seeding around one or two packages (`packageTriples`, `seedAround`). The CLI flags (`scripts/package-flags.ts`; forge, optimize, season, breed-preview) are opt-in: without them every builder makes exactly what it made before, pinned in `tests/deck-packages-defaults.test.ts` (re-take those hashes only from code before a change). The forge's and optimizer's candidate functions live in `scripts/builder-moves.ts`.
- **Head-to-heads** (`public/data/h2h.json`, `scripts/build-h2h.ts`) are rebuilt by every tournament run and by `npm run refresh`. The Deck Lab loads them lazily to breed counter decks, and says when they're missing or older than the recorded events. Beside the raw counts the file has optional `model` and `shrunk` fields: each pairing's estimate shrunk toward the power ratings' prediction (`src/lib/h2hModel.ts`, `h2hFileLookup`); readers (breeder counters, deck-profile matchups) prefer it, and `build-h2h.ts --loeo` checks it leave-one-event-out.
- **Power ratings** (`scripts/ratings.ts`, model in `src/lib/ratingModel.ts`) draw the 90% ranges in `ratings.json` from the full covariance of the fit (`intervals: 'full-covariance'`); `scripts/rating-plan.ts` plans (and with `--play` plays, never recording an event) extra pairings that would narrow them most. Ratings and h2h pool only the sim version and bot of the newest recorded event by default (`selectEvents` in `scripts/event-pool.ts`; `--sim-version` / `--bot` `all` pools them with a warning); an event left out is listed in the file's `pool` field, which `check:data` accepts.
- **CLIs** print usage with `--help` and exit 2 on unknown flags or invalid values. Data-writing ones refuse to overwrite without `--force`: `npm run tournament` starts after the highest recorded event, `scripts/season.ts` defaults to the next season and won't re-run one, and `sim add` / `import-meta.ts` / `import-guides.ts` / `eor-build.ts` / `theorize-ladder.ts` won't overwrite a deck (they keep provenance headers). `scripts/tag-provenance.ts <prefix>` rewrites only the named deck files' headers (e.g. `s2-` after a season), never the sim-ladder lists, and keeps the forge's `// Forged <date>:`, `// Adoption:` and `// Packages:` lines. `data/reviews/` is gitignored output of `scripts/review.ts`. Unmaintained one-offs live in `scripts/archive/`; don't run them.
- **Before committing:** `npm run typecheck && npx vitest run`. `typecheck` is `tsc -b` over the solution `tsconfig.json`, which lists `tsconfig.app.json` (`src/`, DOM), `tsconfig.worker.json` (`src/sim/*.worker.ts`, WebWorker), `tsconfig.node.json` (`scripts/`, `tools/`, no DOM) and `tsconfig.test.json` (`tests/`), all extending `tsconfig.base.json` (strict, `noUnusedLocals`/`Parameters`); then `tools/check-index-access.ts` checks `src/lib` and `src/analysis` with `noUncheckedIndexedAccess`. A bare `npx tsc --noEmit` checks nothing now. `npm run lint` (react-hooks rules only) and `npm run test:cov` are optional; run `npm run check:data` after changing recorded data.
