# Night City Trainer — notes for contributors and agents

- **Stack:** TypeScript, React 18 and Vite 8, with Vitest 5 for tests and tsx for scripts. No backend. The site is a static build for GitHub Pages (`base: './'`, hash routing), deployed by `.github/workflows/pages.yml` (official Pages actions; a `check` job runs `npm run typecheck`, tests, lint, `check:data` and the build on every push and PR, and `deploy` publishes pushes to `main`; actions pinned by SHA). The page loads nothing from another host by itself: the two typefaces are bundled from the `@fontsource/inter` and `@fontsource/rajdhani` packages through `src/ui/fonts.css` (`tests/no-third-party.test.ts`); card art from the card database's host (`src/ui/art.ts`) is the one runtime exception.
- **Engine:** `src/engine/engine.ts` (Game class) implements the Comprehensive Rules saved in `data/raw/official_comprehensive_rules.txt`. Card behaviour lives in `src/engine/scripts/<color>.ts`, keyed by card id from `src/data/cards.json`.
  - `Game` is a facade: setup, the turn loop, accessors and the log are in `engine.ts`; every other method hands over to the function of the same name in `src/engine/game/` (`mods`, `economy`, `zones`, `gigs`, `choices`, `pending`, `history`, `actions`, `combat`), which takes the game first. Scripts, bots and tests keep calling `g.method()`; put new rules code in the module it belongs to, with a one-line method on `Game` if callers need it.
  - Scripts use the `CardScript` hooks in `src/engine/types.ts`.
  - Opt-in agent flags on `Agent` (`types.ts`): `choosesPayment`, `choosesOrder` and `confirmsEndTurn` (a main phase whose only legal action is pass asks the one-option 'action' decision instead of ending the turn by itself). Only human seats set them; bots, clones and play-outs never do, so bot games and pins don't move.
  - When an effect does nothing because its condition fails or it has no target, the log says why: `noEffect()` in `scripts/helpers.ts` (`pick()` logs an empty candidate list itself). Log only (bots never read the log; clones and probes don't log), and only facts both players can see.
  - State must stay plain data, because `Game.clone()` / `probeCopy()` copy it with `copyGameState` (`src/engine/copyState.ts`): the generic `copyState` (throws on a Map, Set, Date or class instance) with each card copied by a spread, so a card keeps exactly its own keys in its own order (`stateHash` hashes `JSON.stringify`, its output is stored in saves and records, and Undo continues from a clone). `CARD_OBJECT_FIELDS` must list every `CardInst` field that is not a primitive: the typecheck fails until it does, and `copyCard` must then copy that field. `tests/copy-state.test.ts` checks the copy against `copyState` and `structuredClone`. `Mod` is a discriminated union on `kind` (`ModKinds` in `types.ts`): add a kind there before using it. Never put functions in mods; player `costMod` filters are plain objects (`CostModFilter`, see `costModMatches`). A `'startOfTurn'` mod must name `untilPlayer` (the types and `modDuration` refuse one without).
  - Which cards' text is active, and in what order, is defined once, in `Game.eachSource` (a visitor; the walk stops when it returns true): `sources()` builds its list on it, and `rawPower` / `hasKw` (`game/mods.ts`) walk it without building a list.
  - `Game.lineage()` is a token shared by a state and every copy `clone()` / `probeCopy()` makes of it (a WeakMap keyed on the state object, never in the state). The bots cache each seat's own Gig plan and archetype per lineage (`planFor`, `seatArchetype` in `src/ai/eval.ts`), which is right because no card is made, removed or changes owner once play starts; a state built any other way (`Game.create`, a structured clone, a view) has its own token.
  - "Next time … this turn" effects from Programs use `g.addDelayed(self, event, data)` together with a `delayed` handler on the script.
  - "First time … each turn" effects read the engine's per-turn history (`g.firstThisTurn(ev.seq, kind, pred)`, `g.turnCount`), not per-card markers.
  - `Game.clone()` drops the log by default; pass `{ keepLog: true }` to keep it (the Play undo snapshot in `src/lib/practiceSession.ts` does).
- **Card data:** `npm run build:data` (`tools/build-data.ts`) regenerates `src/data/cards.json` from `data/raw/sim_catalog.json`.
- **Bundled data in the UI:** read `src/data/*.json` through the typed views: `src/data/index.ts` (types, and `RATINGS` / `SEASONS` / `REVIEW`), and one module per large file (`analysisData.ts`: the analysis summary and per-deck parts loaded on demand, see Decision telemetry; `deckReportsData.ts`, `tournamentIndex.ts`). The Home page is in the entry chunk, so it must not import a large file statically (`tests/home-data.test.tsx` checks; Home loads the deck reports at runtime). `allDecks()` is cached against the stored custom decks and returns a read-only list. The next event's date is in `src/content/event.ts`. A deck's finals report is bundled with the bot that played it (`finals.bot`, `scripts/bundle-reports.ts`: `deep` for Seasons 1 and 2, `hard` since Season 3) and worded by `finalsGamesWords` (`src/lib/playedRecord.ts`: the games alone when the report names no bot).
- **Card mentions:** a card named in UI text shows the card on hover or focus and opens the card dialog on click or tap. The matcher is `src/lib/cardMentions.ts` (pure: full names, unambiguous short forms of 4+ letters, capitals as in the name, whole words, `skip` strings); the components are `MentionText` / `CardMention` in `src/ui/components/CardMention.tsx` (passive span inside a button or link, `MentionRoving` + `rovingProps` for a long log, one `CardDialogHost` in App); the name index and preview load lazily (`mentionRuntime.tsx`), plain text until then. Link by id (`<CardMention id>`) where the data has the card id; match names only in free text, never in players' own text (chat, deck and player names).
- **`data/raw/`** (rules text, card catalog, choom.gg pages) is gitignored and local-only: it is not in the repository or the site, so a fresh clone can't run `build:data` or the choom.gg imports.
- **Decks:** `data/decks/*.txt` (meta-*, ladder-*, guide lists, lists imported from players) and `data/decks/custom/`: `LIBRARY_DIRS` and `libraryDeck()` in `src/lib/library.ts` are the one rule both loaders use (`loadLibrary` in `scripts/lib-node.ts`, `BUILTIN` in `src/lib/browserLibrary.ts`). A deck's kind (`LibraryDeck.kind`, decided once in `kindOf`) is `original` for `nc-` / `s<N>-` files, `custom` in `custom/`, `shared` for a list imported from a shared link (by its Origin "Imported from …", `isImportedOrigin` in `src/lib/importedOrigin.ts`, never by the file name), `meta` / `ladder` by prefix, else `guide`; the gallery calls `shared` "Player lists" (source key `shared`, badge "Player list", credit "site · author"), the runner's quick sets "All player lists", the CLI `--field shared`. A `shared` deck is never a choom.gg guide: `scripts/tag-provenance.ts` leaves its header alone. Retired lists live in `data/decks/archive/` (not loaded by the site or `loadLibrary`; notes in `src/content/deckObjectives/archived.ts`). Parse and export them with `src/engine/deck.ts`. Choom.gg imports are refreshed with `scripts/import-meta.ts` and `scripts/import-guides.ts`.
- **Deck import** (docs/DECK_IMPORT.md; ROADMAP2 §13 goal 3): decks other players shared on choom.gg and cyberpunk-tcg-sim.online come in through three pieces. `tools/import_decks.py` (Python 3.9+, standard library only) is the one piece that touches the network: it reads public pages on those two hosts only, never choom.gg's `/api/` or `/admin`, nor the sim site's `/api/`, `/dashboard` or `/metrics` (`site_of`, kept as a second belt: their robots rules as read on 2026-11-18, however the path is spelled; a redirect off the two sites is not followed), one request at a time at least `--delay` apart (2 s, never under 1), at most 60 pages a run and `--limit` decks a page (20, at most 60), stopping at once on a 403, a 429 or a bot check, reading each host's robots.txt before its first request of a run and keeping to it (`tools/robots.py`: Crawl-delay honoured and over 60 s refused; a robots file it cannot read, or a changed sim-site one, is exit 3), with the plain User-Agent `deck-import-script/1.0` (nothing about the person or the project goes into a request), and writes one file, `deck-import.json` (`kind: 'nct-deck-import'`, schema 1; gitignored, like `deck-import-chosen.json`), with each card as the site wrote it (an id, a compact code or a name). `src/lib/deckImport.ts` (pure; the admin page and the command line share it) reads that file as untrusted input (`readImport`: every string through `cleanText` in `src/lib/cleanText.ts`, which `profile.ts` re-exports, capped by `IMPORT_LIMITS`; a link kept only when it is http(s) on the two sites), matches each reference and never guesses (`resolveRef`: a `cb-` id, the card database's `eid`, a compact code = set letter + print number in base 36 + the number's letter, or the exact name; only own entries of `CARD_BY_ID` count, so "constructor" is not a card), builds and validates the deck (`buildDeck`), says who already has its list (`sameListHolders`: the one-entry-per-list rule of `distinctLists.ts`, the library first, then My decks, then an earlier deck of the import), reads a sim deck-builder link from its address with no request (`decodeDeckBuilder`, `sortLink` / `sortLinks`; `keptOut` is the script's path rule again), and writes a library deck file with its provenance header (`deckFileText`: Origin "Imported from <site>", which `isImportedOrigin` reads (the kind `shared`, and `isOwnerImport`); Added is the day it was collected, and the page's own date, when it gave one, is in the Via line as "published …"; `deckFileProblem` refuses a name that does not read back) and a `needs-owner` placeholder note (`placeholderNote`: one line, `'<file>': importedPlaceholder('<listId>', [<Legends>]),`; the words are defined once, in `importedPlaceholder` in `src/content/deckObjectives/imported.ts`, so a placeholder is one line, not a whole note; the call is then replaced with a full note object, `status: 'owner'` when the owner wrote it). The admin page's last section, "Import decks", is `src/ui/components/AdminDeckImport.tsx` (lazy from `Admin.tsx`; the page fetches nothing from the two sites): paste links (each sorted as Read here / Needs the script / Refused, with why), copy the command (`scriptCommand` percent-encodes what a shell would read), load the script's output, look every deck over (name editable), then "Add to My decks" (`origin: 'imported'`, the source link, a credit line in `notes`), "Download deck files" or "Download for the command line" (`deck-import-chosen.json`, under the names given). `npx tsx scripts/import-links.ts FILE [--write] [--dir] [--prefix] [--notes] [--date] [--force]` (logic in `scripts/import-links-run.ts`) is the library step: it only prints without `--write`; with it, it writes `data/decks/import-<name>.txt` and adds the placeholder line to `src/content/deckObjectives/imported.ts` above `NOTE_MARKER` (never a second entry for a file that has a note, full or placeholder: `hasNoteFor`); never a deck with an unmatched card or an illegal list, never a list the library has, never over a file without `--force`; it ends with what is left (the owner's note, `npm run evidence`, `check:data`, the suite). A deck's name and author are other people's text: cleaned, capped, shown as text only, never through the card-name matcher. Tests: `tests/deck-import.test.ts`, `tests/deck-import-ui.test.tsx`, `tests/import-links-cli.test.ts`, and the script's own `python -m unittest discover -s tools -p "test_*.py"` (made-up pages, no network; a step of the `check` job). The step notes a list with fewer Units than the bred decks' floor (`MIN_BRED_UNITS`, 13) as information only: `tests/breeder-units.test.ts` holds the floor against the trainer's own sources and does not count lists imported from players (real tournament lists run 10 Units; the floor was kept on 2026-11-16, lowering it is the owner's call). The library holds 18 such lists since 2026-11-16 (`data/decks/import-*.txt`: the Discord 5k Celebration Tournament's top 8 and the ten lists of cyberpunk-tcg-sim.online's Season-1 ranked report); their notes are agent-written drafts since 2026-11-16 (`status: 'draft'`, `source: 'list'`: each read off its list and the cards' texts, not checked by the owner; the page says "Draft from the list"), and a deck the script adds later starts as a placeholder again; events 16 to 19 (all 71 decks, recorded the same day) rated them, each on 86 to 106 games, so their ranges are 7 to 8 points either side (the older decks' are about 4). They are named by source and placement, then the Legend trio in the "Ladder:" decks' style ("Discord 5k #1: Smasher / River / Reyes (RYY)", "Ladder S1 #2: V / Smasher / Saburo (RRG)": the letters are the deck's colour pill); the Season-1 lists are anonymous lists the site built for each trio, and their Author line says how. A deck-builder link carries a whole list (700 characters and more), so the provenance block shows a long source link cut (`linkText` in `src/ui/components/Provenance.tsx`: the href and the title keep it whole, and the block's cells break anywhere; `tests/provenance-block.test.tsx`). Library growth has one build limit (`tools/size-budget.ts`): the site search's first-search budget (0.6 to 1.1 kB a deck with its note, of 300 kB; see Site search). Long notes also cost the search itself at first: the 18 drafts restate their cards' effects, and several notes ranked above a card described without its name (2.6 points of top-five recall on the site's pack). Since the same day the search holds a deck's own text back unless the question is about a deck (see Knowledge pack, step 4.9), and the notes cost it nothing. The worker bundles no longer grow with the notes (see Deck objectives).

Each tier's settings are written once, as plain data, in `TIER_SETTINGS` (`src/ai/tiers.ts`); a variant that is not a tier, `hard-main` (Hard without reaction rollouts or the sell lookahead, "Hard (main-phase rollouts only)"; `VARIANT_SETTINGS`, `HARD_MAIN_SPEC`, its own ledger bot), is a `--bot` for every script since 2026-11-24 and no tool's default (measured as a screening bot in `reports/screening-bot-hard-main-2026-11-24.md`: it ranks the library like Hard at Spearman 0.966 in 0.57 to 0.60 of Hard's time; its spreads and transfer to Hard are not measured); `TIER_SPECS` / `HARD_SPEC` (`scripts/agent-spec.ts`) are that table, and `tests/impact-uses.test.ts` checks a spec builds exactly the tier's bot. Every lookahead that plays a move out (deep rollouts and reactions, the reviewer's oracle, `scripts/review-debug.ts`) uses `playOut()` and `makeWorlds()` in `src/ai/playOut.ts`. - **Sims:** `npm run sim -- <catalog|show|vs|test|review|analyze|add>` runs games in worker threads (`scripts/worker.ts`, booted via `worker-boot.mjs`). Both worker pools are a `WorkPool` (`src/lib/workPool.ts`) with a thin adapter and a crash policy: `workerPool()` in `scripts/lib-node.ts` (worker_threads; a crashed job is retried once) and `GamePool` in `src/sim/pool.ts` (Web Workers; a crashed game fails). The give-up limit is computed from the pool's intended size, and stopping a pool settles every running and queued job (the Node pool's `close()` rejects them with "worker pool closed"). `runJobs` keeps one game pool per process (`gamePool()`), so later batches reuse its workers. `--cache` on botcheck, tune, forge, optimize, rank-stability and deck-sensitivity reads games already played from `.cache/games/` (gitignored; `scripts/game-cache.ts`: keyed on the whole job, `SIM_VERSION`, the Node version and a hash of every file the game worker loads). Other scripts: `scripts/tune.ts` (weight tuning), `scripts/optimize.ts` (card-swap search), `scripts/botcheck.ts` (compare bot configs: duplicate format, each deal played twice with the configs swapped, paired interval from `duplicateSummary` in `src/lib/evidence.ts`), `scripts/rank-stability.ts` (SIM-3: the same round robin under two or more bots on the same deals, at `--per 2` or more, since at one deal a pairing its bootstrap resamples nothing and every interval has zero width; Spearman rank correlation with a paired bootstrap, and the decks whose rank or Sim-tier band moved beyond the noise; maths in `src/lib/rankStability.ts`), and `scripts/deck-sensitivity.ts <base> <change>` (review 2026-11-24 D.3, docs/BOT_TOOLKIT.md §12; maths in `src/lib/deckSensitivity.ts`, the configuration reader and report in `scripts/deck-sensitivity-run.ts`): the per-deck sensitivity report that every evaluation or bot change ships beside its strength figure: the same round robin under both configurations (both seats piloted by the one under test; a bot name, a botcheck JSON spec or `'medium+{"weights":{…}}'`), each deck's paired change and rank under each, the decks beyond 2 and 3 SE against chance, Spearman with a paired bootstrap, the share of deals with the same winner, and the change against list features and deck families (BBG pill, V + Adam Smasher, two red Legends, bred, imported); `--cache`, `--out DIR` (JSON with a manifest).
- **Tournaments:** the rules (Swiss, top cut, Bo1/Bo3, seeds) live in `src/lib/tournament.ts`, shared by `npm run tournament -- --field meta --bo 3 --top 8 --bot hard` and the in-browser runner (`#/run`, games run in `src/sim/game.worker.ts` via `src/sim/pool.ts`). Other formats and hand-arranged events (pairings set by hand, manual top-cut seeds, a fixed bracket, round robin and groups, a match list, Bo5 and best-of per bracket round, first-player rules) are an `EventSetup` in `src/lib/eventFormats.ts` (pure, re-exported by `tournament.ts`; the CLI builds it in `scripts/tournament-setup.ts`, the runner's form is `src/lib/eventDraft.ts`). Default Swiss rounds and top cuts keep the table seed scheme, so a plain event is byte-identical to before (pinned in `tests/event-formats.test.ts`); anything arranged uses keyed seeds (event seed + a stable match key). A non-plain event records `setup`, and `custom: true` unless it is a standard Swiss event: custom events count for ratings and head-to-heads game by game, never for titles, top 8s, finishes or Swiss records (`scripts/event-pool.ts`). Round by round uses `beforeRound`; Resume re-runs the setup with `resumePlay`. The runner's entrant picker enters decks several times in bulk (`duplicateAll` / `duplicateDecks` / `setCopies` / `oneCopyEach` / `removeKeys` in `eventDraft.ts`: all or nothing, refused with a reason past `MAX_COPIES` 16 per deck or `MAX_ENTRANTS` 256; hand-set pairings, seeds, slots and matches are never rewritten, names no longer entered show as problems). The default test timeout is 15 s (`test.testTimeout` in `vite.config.ts`, since 2026-11-15): the seeded-game tests take about 2 s alone but sat at 4 to 5 s in a full run with every core busy, and one more test that spawns the forge tipped one over the old 5 s. The build fails when a worker bundle passes its size budget (`tools/size-budget.ts`, the `workerBudget` plugin in `vite.config.ts`); raise a budget only on purpose. `typecheck` is `tsc -b` over the solution `tsconfig.json`, which lists `tsconfig.app.json` (`src/`, DOM), `tsconfig.worker.json` (`src/sim/*.worker.ts`, WebWorker), `tsconfig.node.json` (`scripts/`, `tools/`, no DOM) and `tsconfig.test.json` (`tests/`), all extending `tsconfig.base.json` (strict, `noUnusedLocals`/`Parameters`); then `tools/check-index-access.ts` checks `src/lib` and `src/analysis` with `noUncheckedIndexedAccess`. A bare `npx tsc --noEmit` checks nothing now. `npm run lint` (react-hooks rules only) and `npm run test:cov` are optional; run `npm run check:data` after changing recorded data. Prettier was dropped (2026-11-18): there is no formatter check; `npm run lint` (react-hooks rules) and `npm run typecheck` are the checks. Node 22.12+ (`engines`; `.nvmrc` is `22`).
