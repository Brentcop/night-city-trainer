# Night City Trainer — notes for contributors and agents

- **Stack:** TypeScript, React 18 and Vite 8, with Vitest 5 for tests and tsx for scripts. No backend. The site is a static build for GitHub Pages (`base: './'`, hash routing), deployed by `.github/workflows/pages.yml` (official Pages actions; a `check` job runs `npm run typecheck`, tests, lint, `check:data` and the build on every push and PR, and `deploy` publishes pushes to `main`; actions pinned by SHA). The page loads nothing from another host by itself: the two typefaces are bundled from the `@fontsource/inter` and `@fontsource/rajdhani` packages through `src/ui/fonts.css` (`tests/no-third-party.test.ts`); card art from the card database's host (`src/ui/art.ts`) is the one runtime exception.
- **Engine:** `src/engine/engine.ts` (Game class) implements the Comprehensive Rules saved in `data/raw/official_comprehensive_rules.txt`. Card behaviour lives in `src/engine/scripts/<color>.ts`, keyed by card id from `src/data/cards.json`.
  - `Game` is a facade: setup, the turn loop, accessors and the log are in `engine.ts`; every other method hands over to the function of the same name in `src/engine/game/` (`mods`, `economy`, `zones`, `gigs`, `choices`, `pending`, `history`, `actions`, `combat`), which takes the game first. Scripts, bots and tests keep calling `g.method()`; put new rules code in the module it belongs to, with a one-line method on `Game` if callers need it.
  - Scripts use the `CardScript` hooks in `src/engine/types.ts`.
  - Opt-in agent flags on `Agent` (`types.ts`): `choosesPayment`, `choosesOrder` and `confirmsEndTurn` (a main phase whose only legal action is pass asks the one-option 'action' decision instead of ending the turn by itself). Only human seats set them; bots, clones and play-outs never do, so bot games and pins don't move.
  - When an effect does nothing because its condition fails or it has no target, the log says why: `noEffect()` in `scripts/helpers.ts` (`pick()` logs an empty candidate list itself). Log only (bots never read the log; clones and probes don't log), and only facts both players can see.
  - State must stay plain data, because `Game.clone()` / `probeCopy()` copy it with `copyState` (`src/engine/copyState.ts`, generic, throws on a Map, Set, Date or class instance; `tests/copy-state.test.ts` checks it against `structuredClone`). `Mod` is a discriminated union on `kind` (`ModKinds` in `types.ts`): add a kind there before using it. Never put functions in mods; player `costMod` filters are plain objects (`CostModFilter`, see `costModMatches`). A `'startOfTurn'` mod must name `untilPlayer` (the types and `modDuration` refuse one without).
  - "Next time … this turn" effects from Programs use `g.addDelayed(self, event, data)` together with a `delayed` handler on the script.
  - "First time … each turn" effects read the engine's per-turn history (`g.firstThisTurn(ev.seq, kind, pred)`, `g.turnCount`), not per-card markers.
  - `Game.clone()` drops the log by default; pass `{ keepLog: true }` to keep it (the Play undo snapshot in `src/lib/practiceSession.ts` does).
- **Card data:** `npm run build:data` (`tools/build-data.ts`) regenerates `src/data/cards.json` from `data/raw/sim_catalog.json`.
- **Bundled data in the UI:** read `src/data/*.json` through the typed views: `src/data/index.ts` (types, and `RATINGS` / `SEASONS` / `REVIEW`), and one module per large file (`analysisData.ts`, `deckReportsData.ts`, `tournamentIndex.ts`). The Home page is in the entry chunk, so it must not import a large file statically (`tests/home-data.test.tsx` checks; Home loads the deck reports at runtime). `allDecks()` is cached against the stored custom decks and returns a read-only list. The next event's date is in `src/content/event.ts`.
- **Card mentions:** a card named in UI text shows the card on hover or focus and opens the card dialog on click or tap. The matcher is `src/lib/cardMentions.ts` (pure: full names, unambiguous short forms of 4+ letters, capitals as in the name, whole words, `skip` strings); the components are `MentionText` / `CardMention` in `src/ui/components/CardMention.tsx` (passive span inside a button or link, `MentionRoving` + `rovingProps` for a long log, one `CardDialogHost` in App); the name index and preview load lazily (`mentionRuntime.tsx`), plain text until then. Link by id (`<CardMention id>`) where the data has the card id; match names only in free text, never in players' own text (chat, deck and player names).
- **`data/raw/`** (rules text, card catalog, choom.gg pages) is gitignored and local-only: it is not in the repository or the site, so a fresh clone can't run `build:data` or the choom.gg imports.
- **Decks:** `data/decks/*.txt` (meta-*, guide lists) and `data/decks/custom/`: `LIBRARY_DIRS` and `libraryDeck()` in `src/lib/library.ts` are the one rule both loaders use (`loadLibrary` in `scripts/lib-node.ts`, `BUILTIN` in `src/lib/browserLibrary.ts`). Retired lists live in `data/decks/archive/` (not loaded by the site or `loadLibrary`; notes in `src/content/deckObjectives/archived.ts`). Parse and export them with `src/engine/deck.ts`. Choom.gg imports are refreshed with `scripts/import-meta.ts` and `scripts/import-guides.ts`.
- **Bots:** `src/ai/heuristic.ts` (1-ply lookahead; set `deep: N` for turn rollouts), `src/ai/eval.ts` (weights: `TUNED_WEIGHTS` are the ones `scripts/tune.ts` searches by default; the rest, such as `playOutClamp` and `win`, are fixed defaults; `evaluateTerms()` gives the per-term features that `scripts/eval-calibrate.ts` fits against results; `DEFAULT_WEIGHTS` is the fitted set `calibrated-2026-11` + `rivalLethal` 400 since SIM_VERSION 6, with `goSolo` 0 since SIM_VERSION 8 (the named set keeps its fitted −50.6), used by Medium, Hard and the coach (Easy never reads the weights); named sets, including the old hand weights `hand-2026-10`, are in `src/ai/weightSets.ts` and picked in a bot spec with `"weightSet"`; power that lasts only this turn counts only where it can still matter this turn (`evalPower`), and the next-turn steal estimate uses next turn's power and respects `cantAttack` locks), `src/ai/knowledge.ts` (roles, ratings, Gig plans). Each tier's settings are written once, as plain data, in `TIER_SETTINGS` (`src/ai/tiers.ts`); `TIER_SPECS` / `HARD_SPEC` (`scripts/agent-spec.ts`) are that table, and `tests/impact-uses.test.ts` checks a spec builds exactly the tier's bot. Easy alone sets `easyGuard` (skip a Program that would do nothing; never on clone agents). Every lookahead that plays a move out (deep rollouts and reactions, the reviewer's oracle, `scripts/review-debug.ts`) uses `playOut()` and `makeWorlds()` in `src/ai/playOut.ts`. Docs are in `docs/BOT_TOOLKIT.md`.
  - Package terms: `src/ai/packages.ts` gives a seat the synergy packages its own list is built around (cached by list fingerprint, never in state) and per-position facts. The weights `pkgHold`, `pkgAssembly`, `pkgSteer` and `pkgProtect` in `EvalWeights` are 0 by default, and all 0 is the old bot exactly. Only the deciding seat's own packages count; lookahead clones give the rival seat none (`withoutPackages`). Measure a change with `scripts/package-scoring.ts --out <scratch dir>` (paired games, decisions changed, scarce pieces sold). The coach's package wording is `packageNotes` / `packageWarnings` in `src/ai/coach.ts`, gated by the measured lift in the synergy report (`src/ai/packageLift.ts`: a package is named only when its online-vs-never interval is above 0, worded as an association; with no report, as an unmeasured idea); the Play page loads only the lift slice (`public/data/lift.json`; `liftSlice` / `seatLiftFromSlice` in `src/ai/packageLift.ts`; written with the synergy report and by `npm run refresh`; checked by `check:data`), and only while the coach is on, and sends the seat's table in `CoachRequest.lift`.
  - Position benchmark (INFO-5, docs/BOT_TOOLKIT.md §10): `data/benchmark/suite.json` holds Hard-vs-Hard decision positions stored as seed + decks + the answers before them and rebuilt by replay (`pauseAt` in `src/ai/benchmark.ts`), each option labelled by play-outs to the end of the game with Medium bots in shared worlds (stats in `src/lib/benchmarkStats.ts`). `npx tsx scripts/benchmark.ts <bot> [<bot 2>]` reports regret by decision type and stage in a few seconds, but as built it does not separate Easy from Hard (the labels depend on the continuation bot), so it is not a yardstick yet; `scripts/benchmark-build.ts --force` rebuilds the suite (about 35 minutes). The position replays depend on the engine, the oracle's labels on the Medium bot as well: a change to either fails `tests/benchmark.test.ts`, and the suite must then be rebuilt (last rebuilt 2026-11-14 for SIM_VERSION 9).
- **Sims:** `npm run sim -- <catalog|show|vs|test|review|analyze|add>` runs games in worker threads (`scripts/worker.ts`, booted via `worker-boot.mjs`). Both worker pools are a `WorkPool` (`src/lib/workPool.ts`) with a thin adapter and a crash policy: `workerPool()` in `scripts/lib-node.ts` (worker_threads; a crashed job is retried once) and `GamePool` in `src/sim/pool.ts` (Web Workers; a crashed game fails). The give-up limit is computed from the pool's intended size, and stopping a pool settles every running and queued job (the Node pool's `close()` rejects them with "worker pool closed"). `runJobs` keeps one game pool per process (`gamePool()`), so later batches reuse its workers. `--cache` on botcheck, tune, forge, optimize and rank-stability reads games already played from `.cache/games/` (gitignored; `scripts/game-cache.ts`: keyed on the whole job, `SIM_VERSION`, the Node version and a hash of every file the game worker loads). Other scripts: `scripts/tune.ts` (weight tuning), `scripts/optimize.ts` (card-swap search), `scripts/botcheck.ts` (compare bot configs: duplicate format, each deal played twice with the configs swapped, paired interval from `duplicateSummary` in `src/lib/evidence.ts`), `scripts/rank-stability.ts` (SIM-3: the same round robin under two or more bots on the same deals; Spearman rank correlation with a paired bootstrap, and the decks whose rank or Sim-tier band moved beyond the noise; maths in `src/lib/rankStability.ts`).
- **Tournaments:** the rules (Swiss, top cut, Bo1/Bo3, seeds) live in `src/lib/tournament.ts`, shared by `npm run tournament -- --field meta --bo 3 --top 8 --bot deep` and the in-browser runner (`#/run`, games run in `src/sim/game.worker.ts` via `src/sim/pool.ts`). Other formats and hand-arranged events (pairings set by hand, manual top-cut seeds, a fixed bracket, round robin and groups, a match list, Bo5 and best-of per bracket round, first-player rules) are an `EventSetup` in `src/lib/eventFormats.ts` (pure, re-exported by `tournament.ts`; the CLI builds it in `scripts/tournament-setup.ts`, the runner's form is `src/lib/eventDraft.ts`). Default Swiss rounds and top cuts keep the table seed scheme, so a plain event is byte-identical to before (pinned in `tests/event-formats.test.ts`); anything arranged uses keyed seeds (event seed + a stable match key). A non-plain event records `setup`, and `custom: true` unless it is a standard Swiss event: custom events count for ratings and head-to-heads game by game, never for titles, top 8s, finishes or Swiss records (`scripts/event-pool.ts`). Round by round uses `beforeRound`; Resume re-runs the setup with `resumePlay`. The runner's entrant picker enters decks several times in bulk (`duplicateAll` / `duplicateDecks` / `setCopies` / `oneCopyEach` / `removeKeys` in `eventDraft.ts`: all or nothing, refused with a reason past `MAX_COPIES` 16 per deck or `MAX_ENTRANTS` 256; hand-set pairings, seeds, slots and matches are never rewritten, names no longer entered show as problems). The runner's seed is `initialSeed` / `seedAfterStart` (`eventDraft.ts`): a new random six-digit seed on every visit and after every event starts; a setup link's `s=` is used and kept ("Keep this seed", off otherwise); Resume uses the saved run's own seed. Use `makeBot()` (`src/lib/tournament.ts`) for any game that must replay identically: same code + same seed = same game. Bot and engine fixes change results: every event records `simVersion` (`SIM_VERSION`) and a manifest, and `check:data` fails one without them. Upsets are judged against ratings fitted only on earlier events with the same sim version and bot (`src/lib/eventUpsets.ts`; the games come from `src/lib/ratingGames.ts`, the one extraction `scripts/event-pool.ts` also uses): a match is judged when both decks have `MIN_EARLIER_GAMES` (18) earlier games, and it is an upset when the winner's chance per game (`predictPair`, both seats averaged) was at most `UPSET_MAX_CHANCE` (0.30); `upsetCalibration` gives the evidence for both numbers. Movement around the top-cut places after each Swiss round is `roundMovement` in `src/lib/eventFacts.ts`. Since SIM_VERSION 6 Hard reads no card impact (`impact` 0, plain mulligan; since SIM_VERSION 7 also `sellLookahead: 3`), so re-running `sim analyze` no longer moves recorded games; the coach, `hard-v1` and the deck builders still read `src/data/impact.json`. Recorded games are pinned in `tests/replay-events.test.ts`. Events live in `public/tournaments/` (index `src/data/tournaments.json`); the UI shows their recorded `date` with `RecordedAt` / `formatRecorded` (`src/ui/components/RecordedAt.tsx`). A game that throws is an error in both the CLI and the browser pool (`src/sim/pool.ts`), never a tie.
- **Run manifests:** every result writer attaches one (`src/lib/runManifest.ts`): `gameRunManifest` for runs that play games (CLI scripts, Matchup Lab, Deck Lab), `aggregateManifest` for files pooled from recorded events (`ratings.ts`, `build-h2h.ts`), which is derived from the input events only so an unchanged rebuild stays byte-identical. Deck ids are `deckFingerprint`s. Keep `schema: 1` readable: add optional fields only, or bump the schema. `rulesVersion`, `faqVersion` and `errataVersion` come from `src/lib/rulesVersions.ts` (errata has no published date yet, so it is null); aggregate manifests leave them null. `npm run check:data` (read-only) checks the event index against the event files, h2h coverage, and manifest deck ids against the stored lists.
- **Card impact** (`src/ai/impact.ts`, Deck Lab) is matched by list fingerprint (`listFingerprint`, carried in games as `PlayerState.listId`), never by deck name alone. The season breeder's `data/seasons/deck-impact.json` is keyed by list fingerprint too (`src/lib/seasonDeckImpact.ts`; `season.ts` records under the round robin's lists; an old name-keyed file is refused; `scripts/migrate-deck-impact.ts` re-keys one; `check:data` checks it). Every entry in `src/data/impact.json` has its fingerprint (the legacy name table is gone). A less confounded estimate (landmark, by opponent and seat, shrunk; kept vs sold) is written only into an `--out` directory by `npm run sim -- analyze --impact-adjusted --out DIR` (`src/analysis/impactAdjusted.ts`); no bot reads it. `scripts/card-value-check.ts` rank-correlates the hand-written `cardValue` with the measured numbers. `impactSell` / `impactCards` (default `impact`) switch the sell and card-choice uses one by one; `mulligan: 'plain'` drops the mulligan use.
- **Play UI:** the practice-session logic (undo, concede, errors, recording) is in `src/lib/practiceSession.ts`, driven by the `usePracticeGame` hook (`src/ui/usePracticeGame.ts`). Concede is a session verdict, not an engine action: it stops the loop like Quit, then records the game once as a conceded loss. The setup screen is `src/ui/components/PlaySetup.tsx`; the coach's advice comes from `useCoach` (`src/ui/useCoach.ts`, a worker) and its panel, move toast and scorecard are in `board/CoachPanel.tsx`. A position the coach has already answered in this tab (Undo, or a game resumed here) is answered from memory (32 answers, least recently used out, keyed by the exact text of the `CoachRequest` from `src/lib/exactText.ts`; never stored); `tests/coach-cache.test.ts` pins that Undo and a restore re-ask byte-identical requests and that grades and records are the same with and without it. The coach box shown with a prompt (pick, reason, next best; on phones too) is `CoachBox` in the same file. Every Gig figure, grade name and option name the coach shows goes through `src/lib/coachWords.ts` (nothing above 3 Gigs; the Game review's rating names; "End turn" / "No reaction" for the engine's labels); agreeing with the coach on a rule-decided choice is graded `unscored`, and decisions with fewer than 2 options are not advised (`coachWorthAsking`). Drag-to-act and confirm prompts are in `src/ui/components/board/drag.tsx`. The board setting "Confirm before acting" (`confirmActions`, default on; site default `play.board.confirmActions`) decides whether a drop asks first: off, a drop with one possible action is answered at once (`planDrop`, same option index as the prompt's button, so the record is unchanged), while a drop with two or more actions still asks which; payment choices and session confirmations (Concede, Exit, saves, online verdicts) always ask. Every board overlay, dialog and menu uses `useFocusTrap` (`components/Modal.tsx`): focus in, Tab kept inside, Escape, focus restored; the newest open one takes the keys. Which cards look actionable comes from `boardMarks()` in `board/interaction.ts`, which reads only the pending decision's options. The log drawer is in `board/LogDrawer.tsx`, and bot speed and the session-long panel flags are in `board/prefs.ts`. `layoutMode()` in `board/layout.ts` (via `useViewport()`) picks the layout. On desktop and tablets the board fills the viewport (`.pb-full` in `board.css`; card sizes come from `--cw` / `--tcg-w`). On desktop the hand bar takes the board's spare height and the action dock (prompt first, then All actions) stays inside it, never over your piles; the strip drops the Bot speed caption and shortens Undo / Concede / Exit by container width. On phones (`.pb-phone`, portrait or landscape) it is fixed to the screen with sizes from `phoneLayout()`. Phones show prompts in a panel in `board/PhoneParts.tsx` (also the ☰ game menu and the card reader) placed over a part of the table the decision isn't made on: `promptZones()` (`board/interaction.ts`) names the zones it uses, `phonePanelSlot()` / `slotBox()` (`board/layout.ts`) pick your hand, the rival's field or your field, never a back row (Legends, Gigs, piles) or the banner with End turn; collapsed, it is a button in the strip. Overlapped hand cards on phones carry their name on the visible strip (`.pb-fan-cap`). On every layout, prompt cards on the table are picked on the board (`promptChoices()`). The hover preview renders in a portal (`TcgCard`). Undo restores a snapshot (game state plus a cloned bot) taken before each human main-phase decision and continues with `Game.resume()`. The board setting "End of turn" (`endTurn` in `boardSettings.ts`, default `click`; site default `play.board.endTurn`) is fixed when a game starts and recorded as `endTurnClick` on the practice replay, save and review spec (`rivalEndTurnClick` for the rival online, `OnlineSetup.endTurnClick` per seat from the hello); absent means automatic, so older records replay unchanged. Multi-day games against a person stay automatic (a click would cost the guest a packet round trip). Board settings (paying costs, the side panel's position and display, and the look: accent colours, board and Gig backgrounds, card backs, glow, frames, numbers, motion) are one versioned key `nct.boardSettings.v1` read through `src/lib/boardSettings.ts` and `src/ui/useBoardSettings.ts`, edited in `board/SettingsDialog.tsx` (⚙ on the strip, ⚙ Settings in the phone ☰ menu, and on the setup screen: a Game group, then a Look group with a live mini-board `LookPreview` and one-click `LOOK_PRESETS`, Custom when none matches); look fields added later are optional in storage (older saved settings take the site's default for each, `LATER_FIELDS`). The look is attributes on `<html>` (`applyLook`; index.html sets them before first paint): `data-accent`, `data-card-back`, `data-glow`, `data-frame`, `data-numerals`, and Motion resolved against the device as `data-motion` (full / reduced / off; 'system' = off when the device asks for reduced motion) and `data-ambient` (effects that run all the time: only with full motion, and with 'system' only on a fine pointer, so not on phones); script-driven motion checks `lessMotion()`. Accents and backgrounds are CSS tokens in `src/ui/themes.css` (the hex, rain, skyline and floor backgrounds also draw two masked layers in `BoardFx`, `board/Zones.tsx`, styled at the end of `board.css`, which the live board puts behind its translucent zones); glow, HUD frames, read-out numerals and the motion levels are in `src/ui/hud.css` (site-wide; HUD rules sit under `:where(:root:not([data-frame='plain']))` so they keep the element's own specificity), the board's own parts at the end of `board.css`, card-back patterns in `cards.css`. Decoration never covers card text or art, never uses clip-path on anything focusable, animates only transform and opacity, and changes no box size (the `--cw` budget is untouched); the action marks keep their outline and icon at every glow level. "Choose before/after" payment is a UI layer (`src/lib/eddiePayment.ts`): `answerFor` in Play.tsx holds a costed action until its sources are picked, then answers the engine's own 'pay' decisions from them (`planAnswer`); Automatic never asks: it answers the engine's 'pay' decisions itself with option 0, the automatic rule's own pick (`autoPayAnswer`). Visual replay recording is in `src/lib/replayFrames.ts`. Where a practice game is kept is `src/lib/gameKeeper.ts` (behind `usePracticeGame`): every storage write is checked and a refusal shows in the board's notice; a multi-day entry or an autosave is removed only after the game's record is written; resuming a named save asks first when it would replace another game's autosave or re-finish a recorded game (`ResumeConfirm`); Rematch is built from the game's own record (`rematchOf`). Saved games (`src/lib/savedGames.ts`, UI in `components/SavedGames.tsx`): an autosave (written at each new decision of yours and on page hide, never with `features.savedGames` off; kept by "Save and exit", the Exit dialog's default, and on leaving the page; removed by "Exit and discard", and on finish or concede once the result is recorded) and up to 5 named slots in localStorage, export/import as `kind: 'nct-saved-game'`, `schema: 1`. A save is setup + seeds + your answers + coach grades + a position check (state hash at your last decision, `simVersion`); `PracticeSession.restore()` replays it unpaced (rebuilding Undo snapshots) and refuses, never resumes, a save from another `SIM_VERSION` or one that no longer reaches the saved state (its log can still be read). "⤓ Export game" (game-over dialog, phone ☰ menu) saves the replay with the coach's advice, grade and scores per decision (`src/lib/coachedReplay.ts`, `kind: 'nct-coached-replay'`, schema 1; the session keeps the record on each grade, `CoachedGrade`); `scripts/review.ts --from file` reads it.
- **Online play** (`src/net/`, features `multiplayer` and `chat`; lobby and board in `src/ui/pages/PlayOnline.tsx`, lazy-loaded from Play at `#/play/online` and `#/play/join/<code>`): two people, no server unless the owner configures one. Transport (`transport.ts`): `send` / `onMessage` / `onState` / `close`, implemented by a WebRTC data channel with manual signalling (`webrtc.ts`: the host's invite code and the guest's reply code are each a compressed SDP with its candidates, cleaned by `sanitizeSdp` (no LAN/loopback address the browser didn't hide, `.local` names kept, reflexive/relay `raddr` blanked, `c=`/m-line port/origin as placeholders; LAN addresses kept in same-network mode; optional "leave out my IPv6"); `describeSignal`/`describeText` say what a code shows; prefixes `0`/`1` unlocked (old copies read them), `2` locked with a phrase (`codeLock.ts`: PBKDF2-SHA-256 600,000 rounds + AES-256-GCM, header with purpose and salt bound in; four generated words from a 1,420-word list, ~42 bits; the reply is locked with the invite's key); `decodeSignal` caps what it inflates; `Reassembler` and `splitMessage` (`framing.ts`, shared with the relay) bound the chunk framing (index/count/size checked, 4 messages in flight, 60 s expiry, held-size cap); a **private connection** (`ConnectOptions.relay`, TURN relays from `multiplayer.turnServers` or short-lived credentials from `multiplayer.turnCredentialsUrl`, fetched and checked by `turn.ts` only when a private code is made) sets `iceTransportPolicy: 'relay'` with no STUN, keeps only relay candidates and marks both codes (prefix `3`, or locked purposes `rtc-offer-relay`/`rtc-answer-relay`) so an older copy refuses them instead of connecting directly; the host refuses a reply with any non-relay candidate (`nonRelayCandidates`), the guest answers a private invite privately or not at all (`relayFor`), and on a site that offers private or relay play a guest must tick "Connect directly" (`directOk`) to answer a direct invite; other first digits are "made by a newer version" (`inviteMode`, `NEWER_CODE`); STUN servers from the site config's `multiplayer.iceServers`, empty = same network only; `multiplayer.lockCodes` (default true) sets whether codes start locked), a `BroadcastTransport` for two tabs of one browser (room code, reconnects by itself; both it and the relay are a `RoomTransport`: a peer that leaves is "closed", one that is back "open" again), a `RelayTransport` (`relayTransport.ts`, docs/RELAY_PROTOCOL.md) over a WebSocket to the relay server in `multiplayer.relayUrl` (empty by default: then nothing about it is shown; set, "Through the relay server" is the host's first choice, then Private, then Direct): the invite `r1` + a 16-byte join secret (or locked, purpose `relay-invite`), from which the room id (SHA-256) and an end-to-end AES-256-GCM key (HKDF) are derived, every piece sealed with a per-connection epoch and sequence so the relay sees only room ids, sizes and timing and can't change, reorder, replay or reflect frames; it reconnects with backoff and the session resumes as after any reconnect; the host's last relay invite is `nct.online.relay.v1`), and `loopbackPair()` for tests. Protocol (`protocol.ts`): versioned JSON (`v: 1`), every message parsed into a fresh capped object and refused (noted, never acted on) when malformed; legality now (an answer to the decision actually waiting, by `seq` and option index) is checked by the session. The host's browser runs the real `Game` (`hostGame.ts` `HostGame`: both seats are people; per-seat answers recorded; optional turn timer answering with `defaultAnswer` and logging only the kind of choice, paused while the link is not open (`pauseTimer`/`resumeTimer`, shown on both screens); concede/abandon are session verdicts) and sends the guest only `viewFor(state, 1)` (`view.ts`, pure: the seat turned round to player 0; both decks, the rival's hand, every Eddie and face-down Legends the seat doesn't know masked with positional stand-in uids ≥ `HIDDEN_BASE`; `rng` zeroed; the rival's "adds X to hand" unnamed in the log; a Sell for Turn line stays named because the rules reveal the card, 8.11 / 5.8.2.2) plus its own decision (`viewDecision`). The host's own board also draws `viewFor(state, 0)`, through `ViewGame`. Trust model (said in the lobby): the host's device runs the game, so it is for friendly play; a modified host could see hidden cards. The lobby says, before any code is made, that a direct connection shares each player's internet address with the other player and the STUN service, and that unlocked codes carry it (send them privately); it points to multi-day games as the address-free way; a join link's code is taken out of the address bar (`history.replaceState`). First player: commit-reveal roll (`fair.ts`) picks who chooses (rule 7.5). Sessions (`session.ts` `OnlineHost` / `OnlineGuest`): lobby (deck checked with `validateDeck`; the board shows only deck names, the host's device holds both lists), heartbeat and "connection lost", refusals answered at most `REFUSALS_PER_SECOND` (the rest counted in one note), reconnection in any stage (the guest's resume token `nct.online.guest.v1`, which also keeps its roll secret until the game starts, so a link lost during the roll, the first-or-second choice or a rematch's roll makes the same roll again; a guest back with another secret is refused; the host's save `nct.online.host.v1` = setup + seed + both seats' answers + a state-hash check, restored by replay), chat (`chat.ts`: plain text, 300 characters, rate-limited, mute; kept only in an export), rematch.
