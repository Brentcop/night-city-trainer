# Night City Trainer — notes for contributors and agents

- **Stack:** TypeScript, React 18 and Vite 8, with Vitest 5 for tests and tsx for scripts. No backend. The site is a static build for GitHub Pages (`base: './'`, hash routing), deployed by `.github/workflows/pages.yml` (official Pages actions; a `check` job runs tsc, tests, lint, `check:data` and the build on every push and PR, and `deploy` publishes pushes to `main`; actions pinned by SHA).
- **Engine:** `src/engine/engine.ts` (Game class) implements the Comprehensive Rules saved in `data/raw/official_comprehensive_rules.txt`. Card behaviour lives in `src/engine/scripts/<color>.ts`, keyed by card id from `src/data/cards.json`.
  - Scripts use the `CardScript` hooks in `src/engine/types.ts`.
  - State must stay plain data, because bots `structuredClone` it. Never put functions in mods; player `costMod` filters are plain objects (see `costModMatches`).
  - "Next time … this turn" effects from Programs use `g.addDelayed(self, event, data)` together with a `delayed` handler on the script.
  - "First time … each turn" effects read the engine's per-turn history (`g.firstThisTurn(ev.seq, kind, pred)`, `g.turnCount`), not per-card markers.
  - `Game.clone()` drops the log by default; pass `{ keepLog: true }` to keep it (the Play undo snapshot in `src/lib/practiceSession.ts` does).
- **Card data:** `npm run build:data` (`tools/build-data.ts`) regenerates `src/data/cards.json` from `data/raw/sim_catalog.json`.
- **Bundled data in the UI:** read `src/data/*.json` through the typed views: `src/data/index.ts` (types, and `RATINGS` / `SEASONS` / `REVIEW`), and one module per large file (`analysisData.ts`, `deckReportsData.ts`, `tournamentIndex.ts`). The Home page is in the entry chunk, so it must not import a large file statically (`tests/home-data.test.tsx` checks; Home loads the deck reports at runtime). `allDecks()` is cached against the stored custom decks and returns a read-only list. The next event's date is in `src/content/event.ts`.
- **`data/raw/`** (rules text, card catalog, choom.gg pages) is gitignored and local-only: it is not in the repository or the site, so a fresh clone can't run `build:data` or the choom.gg imports.
- **Decks:** `data/decks/*.txt` (meta-*, guide lists) and `data/decks/custom/`. Retired lists live in `data/decks/archive/` (not loaded by the site or `loadLibrary`; notes in `src/content/deckObjectives/archived.ts`). Parse and export them with `src/engine/deck.ts`. Choom.gg imports are refreshed with `scripts/import-meta.ts` and `scripts/import-guides.ts`.
- **Bots:** `src/ai/heuristic.ts` (1-ply lookahead; set `deep: N` for turn rollouts), `src/ai/eval.ts` (tuned weights), `src/ai/knowledge.ts` (roles, ratings, Gig plans). Docs are in `docs/BOT_TOOLKIT.md`.
- **Sims:** `npm run sim -- <catalog|show|vs|test|review|analyze|add>` runs games in worker threads (`scripts/worker.ts`, booted via `worker-boot.mjs`). Other scripts: `scripts/tune.ts` (weight tuning), `scripts/optimize.ts` (card-swap search), `scripts/botcheck.ts` (compare bot configs).
- **Tournaments:** the rules (Swiss, top cut, Bo1/Bo3, seeds) live in `src/lib/tournament.ts`, shared by `npm run tournament -- --field meta --bo 3 --top 8 --bot deep` and the in-browser runner (`#/run`, games run in `src/sim/game.worker.ts` via `src/sim/pool.ts`). Use `makeBot()` (`src/lib/tournament.ts`) for any game that must replay identically: same code + same seed = same game. Bot and engine fixes change results: every event records `simVersion` (`SIM_VERSION`) and a manifest, and `check:data` fails one without them. The Hard bot also reads `src/data/impact.json`, so re-running `sim analyze` after events are recorded requires a `SIM_VERSION` bump. Recorded games are pinned in `tests/replay-events.test.ts`. Events live in `public/tournaments/` (index `src/data/tournaments.json`). A game that throws is an error in both the CLI and the browser pool (`src/sim/pool.ts`), never a tie.
- **Run manifests:** every result writer attaches one (`src/lib/runManifest.ts`): `gameRunManifest` for runs that play games (CLI scripts, Matchup Lab, Deck Lab), `aggregateManifest` for files pooled from recorded events (`ratings.ts`, `build-h2h.ts`), which is derived from the input events only so an unchanged rebuild stays byte-identical. Deck ids are `deckFingerprint`s. Keep `schema: 1` readable: add optional fields only, or bump the schema. `rulesVersion`, `faqVersion` and `errataVersion` come from `src/lib/rulesVersions.ts` (errata has no published date yet, so it is null); aggregate manifests leave them null. `npm run check:data` (read-only) checks the event index against the event files, h2h coverage, and manifest deck ids against the stored lists.
- **Card impact** (`src/ai/impact.ts`, Deck Lab) is matched by list fingerprint (`listFingerprint`, carried in games as `PlayerState.listId`), never by deck name alone. The name-only entries in the current `src/data/impact.json` are pinned to their lists in `src/analysis/legacyImpactLists.ts`; delete that table once `npm run sim -- analyze` rewrites impact.json with fingerprints.
- **Play UI:** the practice-session logic (undo, concede, errors, recording) is in `src/lib/practiceSession.ts`, driven by the `usePracticeGame` hook (`src/ui/usePracticeGame.ts`). Concede is a session verdict, not an engine action: it stops the loop like Quit, then records the game once as a conceded loss. The setup screen is `src/ui/components/PlaySetup.tsx`; the coach's advice comes from `useCoach` (`src/ui/useCoach.ts`, a worker) and its panel, move toast and scorecard are in `board/CoachPanel.tsx`. Drag-to-act and confirm prompts are in `src/ui/components/board/drag.tsx`. Every board overlay, dialog and menu uses `useFocusTrap` (`components/Modal.tsx`): focus in, Tab kept inside, Escape, focus restored; the newest open one takes the keys. Which cards look actionable comes from `boardMarks()` in `board/interaction.ts`, which reads only the pending decision's options. The log drawer is in `board/LogDrawer.tsx`, and bot speed and the session-long panel flags are in `board/prefs.ts`. `layoutMode()` in `board/layout.ts` (via `useViewport()`) picks the layout. On desktop and tablets the board fills the viewport (`.pb-full` in `board.css`; card sizes come from `--cw` / `--tcg-w`). On phones (`.pb-phone`, portrait or landscape) it is fixed to the screen with sizes from `phoneLayout()`. Phones show prompts in the small right-edge panel in `board/PhoneParts.tsx` (also the ☰ game menu and the card reader). On every layout, prompt cards on the table are picked on the board (`promptChoices()`). The hover preview renders in a portal (`TcgCard`). Undo restores a snapshot (game state plus a cloned bot) taken before each human main-phase decision and continues with `Game.resume()`. Visual replay recording is in `src/lib/replayFrames.ts`.
- **Rules FAQ conformance:** `tests/faq/matrix.ts` (entries in `tests/faq/entries/`) lists every official FAQ ruling by id with our card id, a one-line paraphrase (never the FAQ's wording), a status and its test in `tests/faq/*.test.ts` (titles name `faq:<id prefix>`). The FAQ itself is local-only (`data/raw/official_rules_faq.json`). When it updates: refresh that file, run `npx vitest run tests/faq` (the consistency test lists new and removed ruling ids), triage them in the matrix, then set `FAQ_VERSION` in `src/lib/rulesVersions.ts` to the file's `updated_at`.
- **Deck objectives** (`src/content/deckObjectives/`): one strategy note per library deck (objective, plan, key cards, success signals in a shared vocabulary, risks), keyed by file and tied to the list by `listFingerprint`; shown as "Game plan" on the deck profile. `tests/deck-objectives.test.ts` fails when a deck has no note, a list changed (update `listId` after re-checking the note) or a term is undefined. The owner edits an entry and sets `status: 'owner'`; sim-ladder decks are `needs-owner` placeholders.
- **Deck Lab** (`#/lab`, `src/lib/deckLab.ts`) tunes a submitted deck (browser forge) and breeds decks in the browser.
- **Decision telemetry** (`docs/DECISION_TELEMETRY.md`): `g.telemetry = new DecisionRecorder()` (`src/engine/telemetry.ts`) records every decision, observe-only (clones never record); `src/analysis/decisions.ts` reports card use by mode, stage and Gig standing as association, not value. `npm run sim -- analyze --decisions [--out DIR]`.
- **Head-to-heads** (`public/data/h2h.json`, `scripts/build-h2h.ts`) are rebuilt by every tournament run and by `npm run refresh`. The Deck Lab loads them lazily to breed counter decks, and says when they're missing or older than the recorded events.
- **CLIs** print usage with `--help` and exit 2 on unknown flags or invalid values. Data-writing ones refuse to overwrite without `--force`: `npm run tournament` starts after the highest recorded event, `scripts/season.ts` defaults to the next season and won't re-run one, and `sim add` / `import-meta.ts` / `import-guides.ts` / `eor-build.ts` / `theorize-ladder.ts` won't overwrite a deck (they keep provenance headers). `data/reviews/` is gitignored output of `scripts/review.ts`. Unmaintained one-offs live in `scripts/archive/`; don't run them.
- **Before committing:** `npx tsc --noEmit && npx vitest run`. `npm run lint` (react-hooks rules only) and `npm run test:cov` are optional; run `npm run check:data` after changing recorded data. Node 22.12+ (`engines`; `.nvmrc` is `22`).
