# Project review, 2026-11-13

Six reviewers audited the project at commit `130c28d` (SIM_VERSION 7): the bots, the coach, the post-game review, online play and network privacy, the features added since the 2026-11-10 review, and a walk-through of the running app. None of them changed the repository. This file is the consolidated result; the **Status** column is kept current as fixes land.

The work follows the owner's order: bots, coach, game review, keeping players' IP addresses private, then the visual theme. Decisions taken while the owner was away are listed in [Assumptions](#assumptions-made-while-the-owner-was-away) so they can be reversed.

Severity: **H** high, **M** medium, **L** low. Confidence is *reproduced*, *traced* (followed in code) or *suspected*. ✓ = re-checked against the code by the dispatcher.

## What is working well

- **Hidden information.** Every bot, coach and reviewer lookahead goes through `hideInfo` / `makeWorlds`; the online guest view masks what the seat can't know. The reviewers found one leak, in a card script (NET-3), not in the lookahead.
- **Tier ladder.** Re-measured on version 7: Hard beats Medium 67.9%, Medium beats Easy 76.9% (paired, meta decks). The order is right and the gaps are large enough for a learner to feel.
- **Speed.** Hard takes a median 6.6 ms per decision in Node (worst 351 ms); coach advice a median of about 90 ms (worst 702 ms); a full game review 7–8 s.
- **Coach plumbing.** In about 520 sampled decisions the coach never offered an illegal option and never advised against its own top move. Stale advice is refused at every step (job ids, the pending decision, Undo, restore).
- **Game review core.** One rating path for the worker, the CLI and the screen; forced moves are never rated; a gap must clear 2 paired SE; a review is about 9 kB and storage is quota-safe.
- **Saved data.** Saves, profiles, share links and the site config all validate untrusted input field by field, with caps; there is still no `innerHTML` anywhere.
- **Multi-day packets, exports and profile links carry no IP or device id.**

### Online play and network privacy (`NET`)

**Who learns a player's address today**

| Who | How |
|---|---|
| The other player | From the invite or reply code, then from the connection itself |
| Anyone who sees a code or link (a public channel, a screenshot, browser history) | The code is the SDP, compressed but not encrypted: it contains the public IPv4 and port, and the global IPv6 address if there is one |
| Google's STUN server (the default) | Contacted when a player clicks "Create invite" or "Make my reply code" |
| Google Fonts; the card-art host (`api.netdeck.gg` and its image host) | Requested on every visit, before any action |
| GitHub Pages | The site host. Hash routes never reach it, so codes stay out of its logs |

| ID | Sev | Finding | Fix | Status |
|---|---|---|---|---|
| NET-1 ✓ | H | Invite and reply codes carry the player's IP in plain sight, and the page suggests sending the invite by "any messenger" with Copy link and Share. *Reproduced.* | See the plan below | Open |
| NET-2 | M | There is no way to connect without sharing addresses: the config refuses `turn:` and the connection can't carry credentials or a relay-only policy. | Private-connection mode | Open |

**Plan for keeping addresses private** (serverless now, ready for a server later)

| Stage | What | Needs a server |
|---|---|---|
| 0 | Honest lobby text before any code is made (the code contains your address; send it privately); the code removed from the URL after it is read; multi-day games named as the way to play with no address shared | No |
| 1 | Codes carry only what a connection needs (unhidden LAN addresses dropped); the lobby shows what a code reveals; fonts served from the site | No |
| 2 | Optional passphrase-locked codes (PBKDF2 + AES-GCM), so a code seen by a bystander reveals nothing. The other player still learns the address on a direct connection | No |
| 3 | A "Private connection" mode (relay only) that works when the owner configures a TURN relay, and otherwise refuses with the reason rather than connecting directly | A TURN relay (third-party or the owner's) |
| 4 | A relayed transport behind the existing `Transport` interface, switched on by a config key, with its protocol written down. With a relay, neither player's address reaches the other | Yes; prepared only |
