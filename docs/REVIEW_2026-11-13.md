# Project review, 2026-11-13

Six reviewers audited the project at commit `130c28d` (SIM_VERSION 7): the bots, the coach, the post-game review, online play and network privacy, the features added since the 2026-11-10 review, and a walk-through of the running app. None of them changed the repository. This file is the consolidated result; the **Status** column is kept current as fixes land.

The work follows the owner's order: bots, coach, game review, keeping players' IP addresses private, then the visual theme. Decisions taken while the owner was away are listed in [Assumptions](#assumptions-made-while-the-owner-was-away) so they can be reversed.

Severity: **H** high, **M** medium, **L** low. Confidence is *reproduced*, *traced* (followed in code) or *suspected*. ✓ = re-checked against the code by the dispatcher.

## What is working well

- **Hidden information.** Every bot, coach and reviewer lookahead goes through `hideInfo` / `makeWorlds`; the online guest view masks what the seat can't know. The reviewers found one leak, in a card script (NET-3), not in the lookahead.
- **Tier ladder.** Re-measured on version 7: Hard beats Medium 67.9%, Medium beats Easy 76.9% (paired, meta decks). The order is right and the gaps are large enough for a learner to feel.
- **Speed.** Hard takes a median 6.6 ms per decision in Node (worst 351 ms); coach advice a median of about 90 ms (worst 702 ms); a full game review 7–8 s.
- **Coach plumbing.** In about 520 sampled decisions the coach never offered an illegal option and never advised against its own top move. Stale advice is refused at every step (job ids, the pending decision, Undo, restore).
- **Game review core.** One rating path for the worker, the CLI and the screen; forced moves are never rated; a gap must clear 2 paired SE; a review is about 9 kB and storage is quota-safe.
- **Saved data.** Saves, profiles, share links and the site config all validate untrusted input field by field, with caps; there is still no `innerHTML` anywhere.
- **Multi-day packets, exports and profile links carry no IP or device id.**

### Online play and network privacy (`NET`)

**Who learns a player's address today**

| Who | How |
|---|---|
| The other player | From the invite or reply code, then from the connection itself |
| Anyone who sees a code or link (a public channel, a screenshot, browser history) | The code is the SDP, compressed but not encrypted: it contains the public IPv4 and port, and the global IPv6 address if there is one |
| Google's STUN server (the default) | Contacted when a player clicks "Create invite" or "Make my reply code" |
| The card-art host (`api.netdeck.gg` and its image host) | Requested when a page shows card art (art can be turned off). Google Fonts was contacted on every visit until 2026-11-13; the fonts are now served from the site |
| GitHub Pages | The site host. Hash routes never reach it, so codes stay out of its logs |

## Tuning and breeding study (2026-11-13)

The owner's concern was that the tuner and the breeders don't give consistent or effective results, and that the statistical evidence can't be referenced at a glance. A read-only study measured it on SIM_VERSION 8 (about 168,000 Medium and 3,500 Hard games). The full report is [TUNING_STUDY_2026-11-13.md](TUNING_STUDY_2026-11-13.md); its result files are in `reports/tuning-study-2026-11-13/`.

**What it found**

- **Adopted changes are real but overstated.** All 7 recorded adoptions re-measured positive on 2,800 fresh paired games each, at about half the size claimed (S2-03's package swap: +15.6 claimed, +6.4 [+4.2, +8.6] re-measured).
- **Runs don't agree.** The same tuning step on 5 seeds screened 37–39 different changes out of 40; of 30 pairs of runs, 1 nominated the same change and none the same single-card change.
- **Most real changes are too small for one run to see.** A single-card swap is worth +1.0 point on average (only 15% are above +3); a Standard run reliably adopts only from about +3.5 (cards) and +6 (packages). Settling a +2 change needs about 4,650 paired games, against 896 per run.
- **Bred decks fall back.** They dropped 15.1 points from their season fitness to their Hard version-8 rating; other decks dropped 1.4. 11 of 12 now rate below the mean of their parents.
- **The intervals are honest.** The spread between blocks matches the interval each run reports: the adoption rule is sound, and the problems are power and starting from zero each run.

**Causes, ranked:** the shortlist comes from one run's 112 games of card statistics, which is mostly noise; real changes sit below what a run can detect; nothing carries over between runs; the first look reads the winner 2–4 points high; Medium is a weak stand-in for Hard (about half the gain survives); matchup-specific effects are averaged away; the breeder enters decks with no test against their parent. Ruled out: first-player variance and hidden variance.

## Assumptions made while the owner was away

- **Bots change recorded results (SIM_VERSION 8).** The standing decision is to fix forward, so the events were re-recorded rather than kept behind a flag. Practice saves and multi-day bot games started on version 7 can no longer be resumed (the save's log can still be read). To go back: the tag `archive/sim-v7-pre-bot-review-2026-11-13`.
- **Adoption rule used for bot fixes:** a fix for a plainly wrong play is adopted when its paired interval shows no loss; anything else needs its lower bound above 50%. Hard's gain for the whole package is small (lower bound just under 50% on the meta decks, above it on all decks); the fixes were kept because each removes a visibly wrong play and none measured a loss.
- **S2-01 Mutant (RYY) moved 25.3% → 50.8%** on one event (68 games, 90% range 42–60%). Plausible as noise plus the bot changes; worth a second look before reading much into it.
- **Coach scorecard letter bands (85 / 70 / 55) were left as they are**, although rule-decided moves no longer count, so the same play now scores lower (an Easy-level player: about 80% → 70%).
- **The coach's mulligan is the plain rule** (as Hard's), replacing the impact rule that measured 48.9%.
- **A game recorded on another simulator version can't be reviewed** (new replays are stamped; older unstamped ones are replayed strictly and refused if they diverge). This also applies to games against a person, whose result doesn't depend on the bots; loosening that for PvP is possible later.
- **A multi-day bot game closed as timed out now reads "You ran out of time"** rather than "You conceded".
- **Invite and reply codes are locked with a phrase by default** (`multiplayer.lockCodes`, editable in `#/admin`). It costs the host one more thing to send (the phrase) and the guest one thing to type. Turn the default off if that friction isn't wanted; the lobby keeps a per-game choice either way.
- **The online log now names a card the rival sells**, as practice games do: the rules (8.11, 5.8.2.2) say selling reveals the card.
- **Card art is still requested from the card database's host**, which therefore sees a visitor's address when a page shows art; it can't be moved without hosting the artwork, and the Art switch turns it off. The fonts were moved to the site on 2026-11-13 once the owner approved the download.
- **Limits chosen for multi-day games:** a claim on time is refused unless the host's own clock agrees (15 minutes of skew allowed); a finished game keeps its last packet 30 days; at most 20 finished games are kept.
- **Private and relayed play are built but off**, because both need a service the owner chooses: a TURN relay for Private connection, a small relay server for the relayed mode. To switch on: `#/admin` → Online play, then replace `public/site-config.json`. Static TURN credentials in that public file can be used by anyone at the owner's cost; short-lived ones need a small endpoint. Neither mode has been run against a real TURN server or relay (no third-party service was contacted during this work).
- **When a relay is configured it becomes the default mode**, ahead of Private, ahead of Direct; a guest answering a direct invite on such a site must tick a box first.
- **Exit keeps the game by default** ("Save and exit"); discarding it is the explicit second button.
- **Automatic payment never prompts.** To choose which Eddies or Legends pay, use "Choose before" or "Choose after" in Settings.
- **The next event is taken to end on 2026-12-13** (`home.nextEvent.end`); Home hides the event bar after that date.
- **Saves and multi-day bot games from version 7** are listed with what happened and can be read, exported or deleted, never resumed; they don't count toward the ongoing-games cap.
- **On phones the prompt panel may cover a zone the current decision doesn't use** (the hand during a Gig roll, say); when a decision uses every zone it opens as a button in the strip instead. Reaction and attack-target prompts were placed by the tested rule but not seen live.
- **Field cards are about 7% smaller at 1280–1920 px wide**, the price of fixing a 41 px overflow at 1280×800.
- **The default look changed** (the "Signal" preset: accent-following backs, read-out numerals, soft glow, HUD brackets). The old board is the "Classic" preset; to make it the site default again set `play.board.glow` to `off` and `play.board.frame` to `plain` in `#/admin`.
- **Glow "off" keeps the action marks' own halo**, so what can be acted on never depends on the Glow setting.
